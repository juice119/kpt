# Agent Guidelines & Rules

## Commit Message Rules

커밋 메시지(Commit Message) 작성 시 다음 규칙을 항상 준수합니다.

### 1. 포맷 규격 (Conventional Commits)
`<type>(<scope>): <subject>` 형식으로 작성합니다. (`<scope>`는 선택 사항)

- `feat`: 새로운 기능 추가
- `fix`: 버그 수정
- `docs`: 문서 수정
- `style`: 코드 포맷팅, 세미콜론 누락 등 (기능 코드 변경 없음)
- `refactor`: 코드 리팩토링 (기능 변경 없는 구조 개선)
- `perf`: 성능 향상
- `test`: 테스트 코드 추가 및 수정
- `chore`: 빌드 업무, 패키지 매니저 설정, 기타 변경사항
- `build`: 빌드 시스템 또는 외부 의존성 관련 변경
- `ci`: CI 설정 파일 및 스크립트 변경

### 2. 제목 (Subject) 작성 규칙
- **언어**: 한국어로 작성합니다.
- **길이**: 50자 이내로 명확하고 간결하게 작성합니다.
- **어조**: 명사형 또는 개조식 표현을 사용합니다. (예: `로그인 로직 수정`, `검색 필터 추가`)
- **표기법**: 첫 글자는 소문자로 시작하며, 문장 끝에 마침표(`.`)를 붙이지 않습니다.

### 3. 본문 (Body) 작성 규칙
- 제목만으로 변경 내용이 충분히 설명되는 경우 본문은 생략합니다.
- 본문이 필요한 경우 **'무엇을'**이 아닌 **'왜(Why)'** 변경했는지 원인과 이유를 중심으로 작성합니다.
- 한 줄당 72자 이내로 줄바꿈을 유지합니다.

### 4. 하단 태그 (Footer)
- 이슈 참조 및 닫기 필요 시 하단에 명시합니다. (예: `Closes #12`, `Refs #45`)
- 하향 호환성이 깨지는 변경 사항이 있는 경우 `BREAKING CHANGE: <상세 내용>`을 명시합니다.
